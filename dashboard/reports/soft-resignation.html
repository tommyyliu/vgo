Where should search go?

PlanProposed, 2 Nov 2026

Soft resignation

Soft resignation saves about 29% of search. It also fills half the training window with cheap positions, and its calibration almost never changes anything. This plan keeps a real saving and fixes both problems.

The plan in brief

  • Save every ply's root value, so any rule can be tested on games already played.
  • Make the cheap tail reversible, and play it without noise.
  • Keep every ply on disk, and thin tail plies when training loads them.
  • Decide from measured comeback rates by board and game stage, and leave the rule off where evidence is thin.

What's wrong today

Calibration changes almost nothing

The picker looks for the lowest threshold with under 3% false positives. On mixed boards that almost never happens, so it holds the 0.99 fallback and the rule keeps firing above its own target.

This is a regression. Commit 4799b3f switched the rule off in this case on Aug 2 and called the fallback backwards. Commit 8001051 brought the fallback back on Aug 30, when the loop stopped using the old pipeline.

Half the window is cheap tail

About 48% of plies come after the rule fires. They are searched at 400 simulations and trained at full weight, which works against the 0.99 threshold's stated purpose of keeping that share down. A 32-game run with real tail records measured 59%, so this was already known.

  • A higher threshold helps on the 18 board. From 0.90 to 0.999, errors fall by more than two thirds.
  • On bigger boards, stage matters more. On the 38 board at 0.99, errors fall from 23.2% in the first 15% of the cap to 1.8% past the halfway point.
  • Doomed early games exist, but value alone can't pick them out. About 78% of the earliest 38-board calls were right, yet 0.999 is still wrong 22% of the time.

These games all had cheap tails, and an early concession means a longer one. Some of the early errors may be weak tail play, not bad judgement. The stored results can't separate the two.

A concession is permanent, and the tail is noisy

Once the rule fires, the game stays cheap to the end even if value recovers (lib.rs:226). The tail also keeps root noise and temperature, which fast turns already switch off (generation.rs:564).

Principles

  • Results come from play. Every game plays to a real end, so the rule never sets a label directly.
  • This is a budget decision. The rule moves search away from games that look decided. It makes no claim about who won.
  • No evidence, no discount. Where the data is thin, games get full search.
  • One definition of each rule. Playing a game and replaying it offline must agree, and a test holds them together.

The new flow

During play, a game moves between two states. A game can now leave the tail, and it can enter again later.

The comeback table

This replaces the threshold. It asks one question: when a game looked like this, how often did the trailing side come back?

  • Cells. Each cell is a board band (18, 19–37, 38), a stage (the four columns above), and a value band (0.95, 0.99, 0.999). That's 36 cells.
  • Counting. A game counts once per cell, the first time it reaches that cell, because plies within a game aren't independent.
  • Open cells. A cell opens when the 95% upper bound on its comeback rate is below the target. A cell with few games has a wide bound, so it stays closed.
  • Entering the tail. A seat must sit in open cells for 5 of its own turns in a row.
  • Refreshing. Before each generator starts, the table is rebuilt from the last 1,000 games.

This also handles games that are doomed early. If a cell for an early position with extreme value has few comebacks, it opens by itself, with no floor holding it back. If the data says value can't tell early, it stays closed.

The target is a plain setting, with a default of 5%. No principled number exists for it. 5% is simply AlphaGo Zero's convention, and a reversible tail makes a wrong call cheaper, so we can move it freely.

A fresh run starts with an empty table, so every cell is closed and every game gets full search. Those early games are also the clean ones, because no tail has touched them. We expect that to take about an hour of generation, or longer if early nets don't reach the target.

The work, in order

  1. Save per-ply search data

    Add root_values, search_kl and top_gap to games.jsonl, at a few KB per game. The last two serve the search budget work. Fix the manifest's radius, which records the flag and not the game's board, and add tail_samples.

    generation.rs, generate_continuous.rs

  2. Write one tail rule

    A small TailRule state machine replaces ResignRule and the two near-duplicate branches in the play loop. It takes each ply's root value and says whether the next ply is in the tail. Hard resignation goes too: all 10,580 games in r128-s2000 read resigned: false.

    lib.rs, generation.rs. Removes --resign-disable-fraction, resign_exempt and resigned.

  3. Play the tail clean

    Tail plies drop root noise and temperature, matching fast turns.

    ply_search_config in generation.rs

  4. Thin at load

    Every ply stays on disk. A new --tail-keep setting, default 0.25, drops tail rows before rendering, seeded by game and ply, so it saves memory and can change without regenerating. Window selection counts kept samples, so a 150k window stays 150k.

    dataset.py, learner.py, train-once.py, count_samples in bulk-loop.sh

  5. Replace calibration

    A new tail-calibration.py replays recent games, builds the table and writes tail-table.json, which the generator reads with --tail-table.

    Removes resign-calibration.py, ResignTrial, calibration_trials, CALIBRATION_*, write_calibration, the per-game calibration file, and the bc calls in the loop.

  6. Report what it did

    At each generator start, log one line per board: games, open cells, tail share and comeback rate. A failed build stops the loop with a clear message. Add the same numbers to events.jsonl and a dashboard panel.

    bulk-loop.sh, dashboard/collect.py

How we'll test it

  • Shared fixture. One file of value sequences and expected enter and exit plies, read by a Rust test and a Python test, so the live rule and the offline replay can't drift apart.
  • Reversal. A game that recovers leaves the tail, returns to full budget, and can enter again.
  • Thinning. It's repeatable, keeps every full-search ply, and the window counts kept samples.
  • Bug injection. Each protection gets a deliberate bug, and we watch the test fail.
  • Game digests. Tail play changes, so these change on purpose, with the reason in the commit.
  • Small runs. A short generator run, then a tiny training run, one stage at a time.

Risks and open questions

  • Cold start works against early speed. The rule stays off while nets are weakest, which gives up to 29% of search in the phase where speed matters most. Weak value heads make poor calls anyway, so we accept this for the first run and will watch how long it lasts.
  • The table lags the model. 1,000 games span a few models. A stale table is mildly conservative as nets improve, which is the safe direction.
  • Cells may stay thin. If 36 cells take too long to fill, merge bands before relaxing the bound.
  • Thinning could hurt late-game play. Compare --tail-keep 1.0 and 0.25 on one window, then play the two nets against each other.
  • The tail may flip back and forth. Exit settings are a first guess. Per-ply data will show how often it happens.
  • Validation mix. Thinning before the train and validation split keeps both on the same mix, but makes runs at different keep rates harder to compare. Those comparisons should read full-search plies only.

Left out on purpose

  • A standing 10% of exempt games. The cold start gives clean games for free. It can come back if the table looks wrong.
  • Changing the ply cap. High cap rates are known behaviour, and the roadmap says not to reopen that without new evidence.
  • A smooth budget. That's a larger idea, covered in Where should search go?
  • Using the settled plane as proof a game is decided. Captures can shrink settled regions (lemma A8), so that would need its own proof.
