# Restart measurements: continuous telemetry and indexed radial queries

2026-10-13, AMD Ryzen 9 9950X and NVIDIA RTX 5070 Ti. Changes are based on
`db262d5` plus the uncommitted restart work. Raw outputs are in
[`artifacts/restart-2026-10-13/`](../../artifacts/restart-2026-10-13/), which is
local run data rather than a committed dataset. No training was running.

## What was implemented

The continuous generator now writes append-only startup, interval, and final
performance records, plus short console summaries. Counters distinguish
searched plies from published games/samples, group board sizes and search
stages, separate soft-resigned searches, and report broker timings/batch fill
and process memory. The bulk loop records training/export and generator handoff
events so contention can be identified.

Search timings include inference waits. Broker queue times are position-weighted
and parallel durations overlap. These counters are not additive CPU-time shares.
The profile supplies CPU attribution separately.

## Baseline and choice of optimization

The fixed-position CPU baseline reproduces the previous cost scale: around
0.95 ms per big-board move, 1.30 ms per packed 128 raster, and 236 ms per
200-simulation search with a synthetic evaluator. That synthetic search does
not include neural inference or input rasterization.

A 120-second neural generation profile uses:

- checkpoint `artifacts/r128-s2000/models/update-000006.onnx`;
- radius 1/38, fixed komi 0.01939, cap 312;
- 128 input and policy resolutions, 16 actors, 200 simulations;
- coarse pool 16, widening coefficient 6, maximum 321 candidates;
- leaf batch 4, TensorRT fp16, two slots, maximum batch 32;
- root uniform noise 0.1, opening temperature 1 for 30 plies;
- soft resignation at 0.99 for five own turns, minimum ply 20, tail budget 80;
- seed 50001, progress intervals of 15 seconds, profiling cancellation at 120 seconds.

The profile reaches opening, middle, and late cap thirds. Packed rasterization
is present in 68.24% of sampled CPU stacks; the indexed legal-space candidate
visitor is present in 38.10%. These are inclusive shares and overlap. The main
target is exact continuous fallback queries used to classify settled pixels.

An export metadata bug initially obscured this: the old sidecar advertises one
dense `states` input even though the graph declares packed `bits`, `dense`, and
`scalars`. The backend uses the graph correctly. Export manifests now describe
actual graph inputs/dtypes, and telemetry records the backend's actual layout.
Existing historical sidecars were not bulk rewritten.

## First CPU change

`visit_candidates_within` previously checked the distance to every stone even
when its caller had a retained spatial index and needed only candidates within
a threshold. A stone's radial candidate can reach the query disk only when
its center is closer than `threshold + 2r`.

Indexed finite threshold queries now walk the existing stone buckets within a
conservative bounding square, then apply the same radial-distance cutoff,
projection arithmetic, and legality checks. A coordinate margin protects
bucket-boundary rounding. Other query paths keep the complete scan. Legal
vertices and board-edge candidates are still checked. No approximation,
capture-rule change, or new locality assumption is introduced.

## CPU results

Two paired runs alternate execution order, using the same 32 saved played
positions and a one-second budget per path/board, with the benchmark's warmup
and minimum pass count. Mean of the two reported medians, microseconds:

| Path | Before | After | Time change |
| --- | ---: | ---: | ---: |
| 1/38 packed raster, 128 | 1291.1 | 1117.2 | −13.5% |
| 1/38 packed raster, 256 | 2747.5 | 2360.5 | −14.1% |
| 1/18 packed raster, 128 | 381.6 | 392.6 | +2.9% |
| 1/18 packed raster, 256 | 1111.2 | 1051.6 | −5.4% |

The big-board gain is consistent across the two pairs. Small-board results are
mixed; there is no general small-board speedup claim. A short Clippy check
overlapped the first baseline pair; the second pair ran without compilation
and shows the same big-board improvement. Raw samples include spreads.

Reproduce the paired CPU paths with separately built before/after binaries:

```bash
BEFORE --seconds 1 --only raster
AFTER --seconds 1 --only raster
AFTER --seconds 1 --only raster
BEFORE --seconds 1 --only raster
```

## Neural comparison

One 120-second profile per variant uses the same model and settings above.
Intervals through 30 seconds are excluded from the following comparison to
avoid early-board warmup and the short compilation overlapping the early
baseline. Compare the remaining six 15-second intervals:

| Measurement | Before | After |
| --- | ---: | ---: |
| Searched plies/s | 40.40 | 41.98 |
| Summed encoding time per broker position | 1190.9 µs | 1068.1 µs |
| Published games over the whole run | 18 | 18 |
| Published samples over the whole run | 3120 | 3120 |

The observed searched-ply gain is 3.9%; encoding time per position falls 10.3%.
All 18 common published games have identical final boards and results. Pending
games are deliberately abandoned at the profiling deadline. Counter intervals
sum to final totals, publication totals match manifests, and both runs report
zero broker failures.

These are exploratory throughput observations, not a confidence interval or a
learning-strength result. Game-stage distributions, actor scheduling, GPU batch
composition, and desktop load can affect the comparison. The recipe uses fewer
actors/simulations and a smaller raster than the bulk-loop defaults. Longer
matched measurements at the intended production recipe remain item 2 work;
the equal published-data totals do not establish more training data per hour.

  replay targets under the progress observer.
